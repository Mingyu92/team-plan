多模态 AI PM 能力清单：交互、评估、数据、成本与合规

写给谁：已对照 AI 产品经理能力模型 有基础自查，准备进入图像 / 音频 / 视频相关产品线，或 JD 明确写「多模态」的同学。 目标：给出一份中立、可执行的补课清单——不是「会用多模态模型」的口号，而是你能写进 PRD、评测表、成本表与合规评审的具体能力。 边界：本文是能力模型在多模态场景的特化清单，不替代五维总模型；岗位形态仍先看 岗位类型盘点。

选题启发自磊叔《关于 AI 产品经理的 100 个问题》Q96（仅选题结构，正文为原创）。

一、先对齐：什么叫「多模态 PM」

「多模态」在招聘文案里经常被用得很宽。产品侧建议用输入/输出是否跨模态来落地，而不是用模型名字自我安慰：

形态 典型例子 对 PM 的含义
单模态对话 + 偶尔附图 客服里偶尔识图 多模态是增强能力，评估与成本按「渗透率」单独算
理解型多模态 截图问答、文档/表格理解、视频内容理解 重点在组合意图、跨模态一致性、延迟与失败态
生成型多模态 文生图/视频、配音、口播成片 重点在质量维度拆分、版权与标识、产能与排队
实时多模态 语音通话、看画面边问边答 重点在时序对齐、打断/接管、流式体验与成本爆炸

事实：主流云厂商的多模态计费，通常把图像/音视频折算进 token 或按时长/张计费，单价与纯文本同量级请求往往不在一个数量级（见文末 OpenAI / Anthropic 官方文档，截至 2026-08-06）。
建议：入职或立项第一周，先画出「主路径模态组合」与「单位任务成本量级」，再谈功能清单。

公开面经里，视频向多模态岗常会深挖 Prompt、音画同步、模型调研与 POC（见 B 站多模态视频 AI 产品面经）。那是面试题形态；下文把它翻译成可自查的能力清单，不复述题面答案。

二、总览：五块增量能力（对照五维模型）

多模态 PM 不是另起一套能力模型，而是在五维上叠加强制项：

增量能力 主要落在能力模型哪一维 一句话可执行标准
跨模态交互设计 产品基本功 能写清「多输入如何合成一个意图、失败时用户怎么恢复」
多模态评估体系 数据与评估 能把「好」拆成单模态质量 + 跨模态一致性，并有可回归用例
多模态数据闭环 数据与评估 + 技术认知 能设计采集 / 标注 / 回流字段，而不是只埋「点了赞」
多模态成本与定价 商业判断 能按分辨率、时长、采样率估单位成本，并设降级开关
多模态合规与风险 伦理与合规 能按模态列出标识、版权、造假、生物特征等评审项

下面每块给：要会什么 → 最小可交付物 → 自查勾选。

三、跨模态交互设计

要会什么

单模态产品常见路径是「输入框 / 上传一张图」。多模态产品里，用户可能同时丢：一句指令 + 参考图 + 一段口播 + 时间轴片段。PM 需要定义的是组合意图如何被理解、歧义如何澄清、部分模态失败时如何降级。

最小可交付物

  1. 意图合成表：列出主场景的输入组合（如「文本+图」「纯视频」「语音+画面」），每行写：期望行为、禁止行为、需用户确认的点。
  2. 失败态与接管：某一模态不可用（无麦、图损坏、视频超长）时的 UI 文案与人工/模板兜底；可参考 兜底与反馈设计、Agentic UX 与信任校准。
  3. 时序与对齐约束（音视频向）：可接受的音画偏移阈值、超时策略、是否允许「拆开处理再合成」的 pipeline（产品侧先定阈值，再交给工程）。

自查勾选

  • [ ] PRD 里写清了「多模态输入」而不只是「支持上传图片」
  • [ ] 至少 3 个歧义 case（图文矛盾、口播与字幕冲突、用户只传图不传指令）有明确产品策略
  • [ ] 有可演示的失败态，而不是只演示 Happy Path

四、多模态评估体系

要会什么

纯文本评估可以围绕「对不对 / 好不好读」。多模态输出常要同时看：文本、视觉、音频，以及彼此是否一致（例如口播内容是否匹配画面、字幕是否跟嘴型大致对齐）。「好」必须拆开定义，否则算法和业务会对着两个指标吵架。

最小可交付物

  1. 维度拆解表（按产品形态裁剪）：
维度 测什么 常见误用
单模态质量 OCR/识别准不准、画面清晰度、音色自然度等 用一个「综合分」掩盖短板
跨模态一致性 图文是否矛盾、音画是否同步、指令是否被执行 只评生成好看，不评是否听从用户约束
任务成功 用户目标是否达成（剪辑完成、问题答对、成片可发） 用模型 benchmark 替代业务成功
体验与系统 首帧/首包延迟、失败率、人工接管率 离线分涨了就默认体验涨了
  1. 评测集种子：每种主输入组合 ≥ N 条（N 由风险定，高风险场景宁可少而精），含标准答案或评分细则；方法论见 如何搭建评测集。
  2. 上线门槛：写清「哪几个维度不过就不能全量」——与 能力模型 · 数据与评估 的优秀线对齐。

自查勾选

  • [ ] 「好」的定义可以让算法、设计、运营在一页纸上达成一致
  • [ ] Badcase 能归因到「识别错 / 一致性差 / 延迟炸 / 用户意图歧义」中的至少一类
  • [ ] 离线指标与在线业务指标有对照表，而不是默认等价

五、多模态数据闭环

要会什么

文本产品常靠日志与点踩回流。多模态样本更重：存储贵、标注贵、隐私更敏感。PM 要设计的是采什么、谁标、标什么、回流到哪一层（Prompt / 规则 / 微调 / 供应商反馈），而不是口号式「做数据飞轮」。冷启动手段见 冷启动与数据飞轮。

最小可交付物

  1. 事件字典：记录模态类型、分辨率/时长、用户编辑动作（裁剪、重生成、改 Prompt）、显式反馈、最终是否采用。
  2. 标注规范最小版：一致性怎么判、边界 case 谁裁决；避免「好看就标正」。
  3. 采样策略：全量存原始媒体通常不现实——定义抽样比例、高风险全量、低风险降采样。

自查勾选

  • [ ] 上线清单里有「多模态回流字段」，不是上线后补埋点
  • [ ] 标注成本进了季度预算，而不是默认「算法自己找数据」
  • [ ] 涉及人脸、声纹、未成年人等内容时，采集前已过合规/个保评审入口

六、多模态成本结构与商业取舍

要会什么

事实（厂商公开文档，访问 2026-08-06）：

  • Anthropic：图像按视觉 token 计费，大致随分辨率缩放；官方 Vision 文档给出按尺寸估算 token 的方法，再用模型输入单价折算成本。见 Claude Vision。
  • OpenAI：图像输入计入上下文 token，并提供 detail（如 low/high）等影响清晰度与 token 消耗的参数；以官方 Images / Vision 指南与定价页为准（价格会变，估算前需重核）。

视频与实时语音通常还会叠加时长、采样率、是否做抽帧/转写等工程选择——单价公式因供应商而异，PM 不必背死数字，但必须会问：「单位任务默认分辨率/时长是多少？降一级清晰度省多少、损多少效果？」

最小可交付物

  1. 单位任务成本卡：主路径一次成功调用的输入构成（文本 + 图/音/视）与量级估算；模板可复用 成本测算入门、模型选型框架。
  2. 降级开关：低清预览 → 高清精修；先抽关键帧再全片；商业 API 够用 vs 需微调/自部署的分流条件（面经中的调研框架可作面试准备参考，落地时仍以你司 POC 指标为准）。
  3. 配额与定价含义：免费额度、积分、队列——生成类产品尤其要把「产能」当成产品能力，而不是纯运维问题；商业化模式见 AI 定价与商业化。

自查勾选

  • [ ] 能向老板讲清「日活 × 渗透率 × 单次成本」的粗账，而不是只报模型官网单价
  • [ ] PRD 写了默认清晰度/时长上限与超限策略
  • [ ] 成本超标时有产品侧可执行的降级，而不只是「让算法再优化一下」

七、多模态合规与风险

要会什么

生成式服务若向境内公众提供文本/图片/音频/视频等内容，需对照《生成式人工智能服务管理暂行办法》等要求；图片/视频等深度合成内容还有标识与相关规定。产品清单总表见 生成式 AI 合规设计清单（本文不构成法律意见）。

多模态场景下，建议按模态拆风险，避免只做「文本敏感词」：

模态 常见产品风险（示例） PM 最少动作
图像 侵权素材、人脸滥用、虚假新闻配图 输入来源与输出标识、举报与下架路径
音频 仿声诈骗、未授权音色 音色授权链路、高风险场景人工复核
视频 深度伪造、音画合成误导 显式/隐式标识、传播侧提示、重大题材升级
跨模态组合 「图文一致但整体虚假」 一致性检测之外的内容安全与人工抽检

自查勾选

  • [ ] 立项材料里写清适用哪些公开规范（并经法务确认）
  • [ ] 生成内容有标识与投诉入口，而不是上线后补
  • [ ] 高风险动作（模仿真人、涉及未成年人等）有默认拒绝或强制确认策略

八、怎么用这份清单补课（30 天可执行版）

按 能力模型 的打分习惯，多模态方向建议「一次只补两块」：

周次 动作 完成定义
第 1 周 画主路径模态组合 + 单位成本卡 能口头讲清成本量级与降级开关
第 2 周 写一页「好」的拆解 + 20 条种子评测 算法/设计能按同一表格打分
第 3 周 补失败态与意图歧义 case 演示里至少有 2 个非 Happy Path
第 4 周 过一遍合规清单（图像/音/视频相关项） 法务或合规接口人给出书面/纪要反馈

若你投的是视频向应用岗，可把面经里的高频深挖点（Prompt、音画同步、模型 POC）当作面试演练提纲，用本文第三至六节的交付物当答法骨架——先有交付物，再讲故事。
