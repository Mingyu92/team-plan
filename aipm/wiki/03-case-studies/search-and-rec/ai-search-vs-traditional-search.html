AI 搜索 vs 传统搜索:交互范式与商业模式的双重颠覆

分类:搜推 体验时间:2026 年 7 月

一、产品背景

传统搜索的默认契约是:你给关键词,我给十条蓝链,综合与判断留给你。AI 搜索把契约改成:你给自然语言问题,我先给一段可直接使用的综合答案,网页变成可回溯的依据,而不是唯一交付物。这场变化不是「多一个 AI 摘要模块」,而是交互范式与商业模式同时被改写——前者决定用户还要不要点开结果页,后者决定广告库存还能不能按旧逻辑卖。

本篇是范式对比,不以单一产品为对象。三条可对照的产品路径(数字与细节一律引用已有单品案例,本文不新造):

路径 代表 一句话策略 详案
独立答案引擎 Perplexity 答案 + 引用溯源为主产品;2026-02 起公开弃广告,押订阅与入口 Perplexity 案例
入口上的答案层防御 Google AI Overviews / AI Mode 把生成式回答嵌回全球最大搜索入口,同时把广告迁入答案面 Google AI Mode 案例
超级框 + 工具闭环 夸克 搜索/提问/网址同一入口,答案后再接到总结、创作、文件等任务工具 夸克案例

规模量级本身就说明「范式」与「入口」不是同一战场:Google 官方口径全球搜索量超过 5 万亿次/年(2025-01 广告商业博客脚注);AI Mode 在 2026-05 I/O 称已超过 10 亿月用户。Perplexity 侧第三方口径月查询约 7.8 亿次、2026 年初 MAU 超 4500 万、ARR 在 2026-03 突破 4.5 亿美元(详见 Perplexity 案例)。夸克则未在公开材料中披露可比的搜索量/收入数字(详见夸克案例)。流量级差巨大,但交互命题已经共享——用户越来越期待「先看结论」,平台则必须回答:结论页还卖不卖广告、卖什么、卖给谁。

二、核心功能拆解:交互范式从「十蓝链」到「先答案」

2.1 两条主流程对照

环节 传统搜索 AI 搜索(答案引擎范式)
输入 关键词、少量运算符;用户需「搜索化」表达 自然语言问题、可多轮追问;夸克等产品还会把网址导航收进同一框
系统目标 召回并排序候选网页/文档 检索 → 综合 → 生成可读答案,并保留回网页的路径
第一屏交付物 标题、摘要片段、广告与自然结果混排的链接列表 结构化综合回答(+ 来源入口);传统分栏结果可并存或退后
用户劳动 自行打开多页、比对、摘要 先消费结论,再按需下钻原文或追问
任务边界 以「找到页」为完成 以「得到可用答案 / 进入下一步动作」为完成

传统搜索把「理解问题」外包给用户的关键词技巧;AI 搜索把「综合多源」产品化。Google 的拆法是双表面:AI Overviews 自动出现在结果页顶部,守「第一屏答案」与广告位;AI Mode 需用户主动进入,承接更长、可追问的复杂问题——Labs 早期反馈称 AI Mode 查询平均长度约为传统搜索的 2 倍(详见 Google 案例)。Perplexity 则几乎没有「先给十链再可选摘要」的经典 SERP 心智,默认就是答案引擎链路。夸克公开页把输入框写成「搜索、提问或输入网址」,意图是降低范式迁移成本:用户不必先决定「今天用搜索还是用聊天」。

2.2 交互上真正被颠覆的三件事

  1. 完成定义变了。 传统搜索的成功往往落在点击与停留;答案引擎的成功更接近「用户是否带着结论离开、或带着结论继续追问/办事」。面试里常考的北极星差异,本质就在这里——详见文末《AI 搜索的北极星指标怎么定》。
  2. 会话取代单次查询。 Threads / 相关追问 / AI Mode 多轮,把一次 SERP 变成可收敛的任务流。Deep Research 一类能力进一步把「搜」拉长成「研」——官方与单品案例中的 fan-out、多步检索描述,说明交互时长与成本结构同步上升(详见 Google / Perplexity 案例,本文不展开引用控件细节)。
  3. 答案之后还有动作。 Perplexity 的 Shopping/Finance 卡片与 Comet 浏览器、夸克的总结/创作/PDF/网盘、Google 在 Mode 内推进的购物与 agentic 履约,都在把范式从「信息检索」推到「决策与执行」。入口争夺(Comet、Atlas、浏览器侧边栏)之所以重要,是因为范式变了之后,「谁打开第一屏」决定后续所有动作的分发权——Perplexity 案例写明:Comet 2026 Q1 月活约 1800 万,并视浏览器为操作系统级入口。

主题边界:引用角标怎么点、来源列表怎么排、信任与幻觉如何产品化,属于答案引擎的信任机制专题,见 答案引擎的引用与信任设计。本篇只承认「可回溯来源」是新范式的标配能力,不展开控件级设计。

2.3 三种落地形态,同一范式

形态 用户感知 与传统搜索的关系
独立答案引擎(Perplexity) 打开即答案 几乎替代经典 SERP 心智
嵌在 SERP 的答案层(Overviews) + 进阶 Mode 有时自动出现摘要,复杂题进 Mode 寄生并改造传统结果页,蓝链仍在
超级框 + 工具带(夸克) 同一入口兼容旧习惯,答案后进工具 用兼容换迁移,再用工具提高「任务完成」密度

对 PM 而言:争论「算不算 AI 搜索」意义不大;更有用的是问——第一屏交付的是链接还是结论?用户能否不离开产品完成下一步?

三、技术方案推测

以下为基于三篇单品案例公开表现的范式级推测,各厂商未完整公开检索与生成管线,请勿当作确定性技术结论。

  • 传统搜索(已知产品逻辑):爬取/索引 → 查询理解 → 多阶段召回 → Learning to Rank → 混排广告与自然结果。优化目标长期贴近点击、停留、商业转化等可拍卖信号。
  • AI 搜索(推测的共性骨架):在检索之上叠加生成——问题理解/改写 →(复杂题)子查询拆解与并行检索 → 片段排序去重 → 将证据喂给大模型生成综合叙述 → 将来源标识回填到答案面。产品表现上接近 RAG,但是否统一框架、是否每问都实时检索,因厂而异(三篇案例均作此保留)。
  • 与传统栈的关键差别(推测):排序目标从「哪条标题最值得被点」部分转向「哪些片段最适合被模型引用综合」;延迟与边际成本从「一次检索」变成「检索 + 生成(+ 可能的多步 fan-out)」,因此路由(简单查询走摘要/列表、难题走 Deep Research/Mode)本身就是产品决策,而不只是工程优化。
  • 入口与 Agent 层(推测):浏览器侧栏、跨页操作、代填代购等,是在答案范式之上再叠「感知页面 → 规划动作 → 执行」循环;这会进一步拉高单次任务成本,并倒逼商业模式不能只靠「多展示几次蓝链广告」。

技术细节与引用对齐算法不是本篇重点;PM 只需抓住一句:交互改成「先答案」,成本结构就不再等于传统搜索的 CPC 机器。

四、商业模式:广告机器 vs 信任订阅的分叉

交互范式一变,变现逻辑立刻分叉。核心冲突是:当第一屏已经是「结论」时,用户还需要点广告主的着陆页吗?用户还会相信这段结论吗?

4.1 对照表

维度 传统搜索 Google 答案层防御 Perplexity 答案引擎 夸克(公开形态)
变现主轴 搜索广告(+购物等) 广告库存迁入 Overviews / Mode 答案面 2026-02 起放弃广告;订阅 + API + 内容分成探索 个人工具/会员与搜索 API 等方向可观察;经营数字未披露
答案与广告关系 用户默认结果含推广 Sponsored 标注下,广告可在 Overview 上/下/内,Mode 内可在答下或嵌入 公开理由:答案旁广告会损害可信度 产品页宣传浏览搜索「无广告」(以当时页面为准,非永久承诺)
定价可见性 广告主侧拍卖为主 沿用 Search/Shopping/PMax 等;广告主通常不能单独「只要 Overview」 Free / Pro $20/月 / Max $200/月等阶梯;Sonar API 按 Token+请求+检索深度计费 标准个人价目表本次单品案例未核实到
战略命题 最大化可商业化查询的匹配与点击 守住入口与广告机器,缩短发现→决策 用无广告与付费意愿换信任定位 用超级入口+工具留存,再探索 B 端能力输出

数字与机制的出处见 Google AI Mode 与 Perplexity;夸克侧「未披露」边界见 夸克案例。第三方曾统计 AI Overviews 覆盖约 48% 的 Google 查询、以及 Overview 旁广告渗透变化等,口径属第三方、且会漂移——引用时请回单品案例核对,本文不另造新数。

4.2 为什么不能互相抄作业

  • 入口方(Google) 的北极星贴近「发现到转化的商业路径 + 广告主库存」。答案层若只摘要不点击,会压缩旧曝光路径,因此必须把广告设计成答案面的「helpful next step」,并用敏感垂类限制、Sponsored 标注等降低污染感(详见 Google 案例)。
  • 信任方(Perplexity) 的北极星贴近「用户是否相信这句话、是否愿意为可信答案付费」。它曾试过相关问题区赞助、答案旁 Sponsored 视频等(CPM 一度很高),却在验证信任受损后整条撤回,转而追逐订阅年化目标,并用 Comet Plus 等与出版商分成探索「给内容源付费」(详见 Perplexity 案例)。
  • 工具方(夸克) 更接近「搜索当入口、工具当留存与增值」:答案完成不等于任务完成,商业化可能长在会员权益、文件/创作能力与开放平台,而非先复制一套 CPC 答案广告——但公开财务未证实,只能当路径假说。

一句话:同一交互(答案旁出现商品或推广)在入口方是库存迁移,在信任方可能是定位自杀。 写 PRD 前先写清卖的是点击、信任还是任务完成,再决定广告是一等公民还是禁区。

五、PM 视角的启示

  1. 先画清「完成定义」,再画信息架构。 若 KPI 仍是经典 CTR/分页点击,却强行上默认 AI 摘要,会自己打自己的分发与广告模型;若 KPI 是「可核验的答案采纳 / 任务完成」,却死守十蓝链首页,用户会流向答案引擎。Overviews(默认层)+ Mode(进阶层)是大入口的渐进迁移范例;没有超级入口的团队,更应狠做场景取舍,避免「既不像搜索又不像助手」。
  2. 商业模式必须与信任定位同向,不能先跑通再后悔。 Perplexity「试了又撤」说明:在回答型产品里,广告与可信度的冲突比传统搜索尖锐得多。Google 选择迁广告、Perplexity 选择弃广告,两边都自洽——抄错边才会同时丢掉收入叙事与用户叙事。
  3. 范式竞争的下一跳是入口与「答案之后」。 当综合答案的边际体验差收窄,分发位置(浏览器、系统框、超级 App)与后续动作(购物、总结、创作、代操作)会决定复访。做搜推 AI 时,不要只盯模型正确率;问自己:用户看完结论下一步去哪、这一步是否还在我产品内、这一步如何计量与变现。
