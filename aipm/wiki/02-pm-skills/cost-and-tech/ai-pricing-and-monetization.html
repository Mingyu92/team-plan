AI 产品定价与商业化：订阅、Token、按结果怎么选

信息状态：决策框架｜最后核验：2026-08-06
产品/API 公开价目以官方页为准；毛利率无经审计财报支撑时只给框架与示意量级，不作行业红线。

AI 产品的定价，本质不是「定一个好听的月费」，而是把不确定的推理成本，翻译成用户能理解、愿付费、你也算得清的商业契约。助手赛道怎么赚钱，见案例合集 助手类产品的商业化路径；本文把那些结论升级成可复用的选型决策树，并回答三个 PM 常被追问的问题：五种模式怎么选、什么时候别对 C 端透传 Token 账单、成本底线怎么估。

选题启发自磊叔《关于 AI 产品经理的 100 个问题》Q75 / Q76 / Q78；正文为原创框架，不摘录该 PDF 答案。

一、先对齐：你在卖什么？

定模式前，先写清三句话（写不出来就别开价）：

问题 写清楚什么 写不清的后果
用户买的是什么？ 确定性（包月额度）、弹性（按量）、结果（线索/工单完结）、还是治理（席位+合规） 订阅与按量混说，客诉与续费崩
成本怎么随用量变？ 单次调用成本区间、重度用户尾巴、是否可异步/可缓存 免费层或包干席位被打穿
免费层算不算成功？ 留存、分发、广告库存、首单授权……哪一项可独立成立 用单一付费转化率考核整盘，假设过乐观

成本怎么拆、怎么估，用 LLM 成本测算入门 的模板；账太贵再看 降本手段盘点。定价文不重复价格表，只在需要锚点时引用官方公开价。

二、五种常见模式（对照表）

与面试题 AI 产品的商业模式与定价、助手商业化合集一致，对外可讲清这五类（可组合，但主叙事通常只能有一个）：

# 模式 钱怎么进来 适合信号 主要风险
1 订阅（含额度） 月/年费；卖模型档、额度、高峰优先、Agent 长跑 用户能感知「不够用」，愿为稳定体验付月费 重度用户薅包干；阶梯过陡转化极低
2 按量（Token / 次 / 积分） 用量 × 单价；成本与收入近似线性 API、开发者平台、企业内部「真实消耗可见」 C 端账单不可预期；大客流失
3 按结果 / 效果付费 按线索、完结工单、合格交付物等收费 结果可观测、可归因、合同可写清 归因扯皮；模型失败时谁买单
4 Freemium + 广告 / 交易导流 免费养规模；广告或订单/抽成补现金 超大免费盘，或自有履约中台 信任与公正性；有对话无订单
5 企业：席位 + 用量（或封顶） 低席位费 + API 费率用量，或席位包额度 要 SSO/审计/数据驻留；用量方差大 销售周期长；包干被少数重度用户打穿

三、决策树：五种模式怎么选

把助手合集的「先问履约、再问月费、最后问广告」升格为通用树。从上到下问，先命中的优先试主模式；辅模式可并行探索，但对外主叙事保持一条。

Q0  你的产品是否主要卖「模型能力给开发者/嵌入方」？
    ├─ 是 → 【2 按量 Token/次】为主；可加预付包/承诺用量折扣
    │        企业大客再叠【5 席位+用量/封顶】
    └─ 否 → Q1

Q1  公司是否有可控的商品/履约/支付中台，且对话能接到下单或履约？
    ├─ 是 → 【4 交易导流】可作主叙事；订阅/广告仅作辅
    │        （北星：下单率、复购、单均贡献，而非强行对标内容助手打开次数）
    └─ 否 → Q2

Q2  用户是否需要「账单可预期」，且愿意为额度/档位付月费？
    ├─ 是，且用量方差可控 → 【1 订阅含额度】
    │        免费层负责触顶转化；收费点放在高算力 Agent/办公额度
    ├─ 是，但组织内用量方差极大 / 要治理合规 → 【5 席位 + 用量】
    │        （Claude Enterprise「席位费 + API 费率」即此类公开结构）
    └─ 否 → Q3

Q3  结果是否可观测、可归因、合同能写清「什么叫成功」？
    ├─ 是（如合格线索、关闭工单、交付物验收）→ 【3 按结果】可试点
    │        建议先小流量 + 人工抽检归因，再扩合同
    └─ 否 → Q4

Q4  是否有超大免费流量，且必须长期维持「聊天不设墙」？
    ├─ 是 → 【4 Freemium + 广告】补免费盘现金流；或接受货币化后置到云/API/生态位
    └─ 否 → 回到成本模板：先砍范围/降本，再谈定价；不要用「先免费再想」代替决策

组合拳怎么打（避免左右互搏）

主叙事 常见辅路径 产品上要统一的事
订阅 API、轻度广告 免费聊天别设硬墙；墙设在额度/模型档
交易 轻度会员 指标用交易漏斗，不要用 MAU×拍脑袋转化率当已验证 ARR
API 按量 预付包、企业合同 C 端卖确定性，API 卖弹性——双轨说清
按结果 底价订阅或按量兜底 合同写清失败归因与封顶，避免「全或无」把你做穿

四、Token 计费劝退：什么时候别对用户透传

对平台/内部：按 Token 算账几乎永远有用（预算、路由、降本）。
对 C 端用户：把「输入/输出百万 Token 单价」直接做成账单，常常是体验事故。

出现以下任一条件，优先改成额度包月、积分、按次、或结果价，而不是裸 Token：

  1. 用户无法预估下一句要花多少
    多轮历史、系统 Prompt、工具定义、RAG 片段都算输入；用户以为在「聊一句」，实际在烧上下文。账单抖动 → 退订与客诉。
  2. 输出单价显著高于输入，且产品鼓励长答/Agent 多步
    公开 API 上输出常为输入的约 5–6 倍量级（见上表）。用户越「用得爽」，你越难用透明 Token 价解释「为什么这一下特别贵」。
  3. 任务边界模糊、失败要重试
    重试、换模型、人工兜底若仍按 Token 向用户加价，等于惩罚探索行为。
  4. 采购决策者与使用者分离（常见 B 端）
    业务要弹性，财务要封顶：更适合席位 + 共享额度池 / 支出上限，而不是每人一张浮动 Token 账单。
  5. 竞品心智已是「包月助手」
    在 ChatGPT / Claude 式分层已教育市场的品类里，突然改成「看 Token 流水」会抬高理解成本，除非你明确卖的是开发者 API。

仍应对用户「用量可见」的做法（不等于裸 Token 价）：进度条式额度、接近上限告警、高峰降速说明、企业支出 cap——面试追问里的「成本不可预期怎么办」同一套路，见 商业模式面试题。

五、成本底线：框架 + 举例（不做伪精确红线）

公开财报若未拆「AI 推理毛利率」，不要编造「必须 ≥ xx%」的行业红线。对内评审用可证伪框架：

5.1 底线不等式（单位：同一周期，如月）

贡献毛利 ≈ 收入 − 变动成本（模型 API / 推理 + 与用量线性相关的向量库等）
          − 应分摊的变动人力（按量增长的标注抽检、人工兜底）

要可持续（示意）：
  贡献毛利 > 0
  且  贡献毛利 − 获客与固定研发摊销  在规划期内能转正（或有明确补贴叙事）

「变动成本」用 成本测算模板 估；「能不能降」用 降本盘点。毛利率目标是公司财务假设，不是本文可引用的外部事实。

5.2 三种常见定价的底线问法

模式 底线问句 举例（示意量级，非标准）
订阅 付费用户 ARPU，能否覆盖「该档用户」的 P90 推理成本 + 人工兜底？ 若某档月费 $20，而 P90 用户月推理已接近或超过该档对应成本带，要么涨档（Max 式倍数）、要么限速/降模型，要么接受该档亏损获客
按量 卖出价是否覆盖「标价 Token × 实际膨胀系数」？ 实际膨胀常来自：隐藏系统 Prompt、多轮历史、工具定义、重试、Agent 步数。售价按「用户可见字数」定、成本按「全量 Prompt」计，是经典亏法
按结果 单次成功结果的收入，能否覆盖「成功路径 + 失败重试 + 人工抽检」的期望成本？ 若平均 3 次生成 + 1 次人工验收才成 1 单，成本按 3+1 计，收入按 1 计

5.3 免费层打平反推（评审一页纸）

延续助手合集做法：先用成本模板估出免费层月度推理区间，再反推：

  • 订阅：需要多少付费用户 × ARPU
  • 广告：需要多少有效库存 × 怎样的 eCPM（若无实测，只标情景）
  • 交易：需要多少单 × 单均贡献（扣补贴与履约）

缺公开分母时，转化率与 ARR 只作情景上下界，写入假设表，不写进「已验证」。

5.4 迷你算例（把底线说清楚即可）

沿用成本文量级感：DAU 10 万、渗透 30%、人均日调 5 次、主力档模型，粗算月模型成本可到约 2.5 万美元 量级（详见 llm-cost-101 完整假设）。

若该功能对用户全免费、又无广告/交易第二条腿，则「商业化」问题先变成：谁补贴这 2.5 万+/月，补贴到什么指标算成功——而不是先设计精美价目表。若改为 Pro 档订阅承接重度用量，应用本档用户的真实分位成本做压力测试，而不是用「平均用户」自我安慰。

六、给 PM 的落地清单

  1. 一页写清：主模式、辅模式、免费层成功标准、成本模板链接、访问日官方价目截图或链接。
  2. 收费点对齐高意图 + 高边际成本：Agent 长跑、高档模型、深度研究、企业治理——而不是打断闲聊。
  3. 包干必做分位：看 P90/P99 用量，不看均值；必要时「席位 + 用量」或超额按量。
  4. 对外数字降级：官方定价可写进 PRD；媒体收入拆分、匿名转化率默认存疑。
  5. 模式可改，契约要稳：调价与改计量方式提前公告；企业合同写清封顶与超额。
