AI 产品成本测算入门:token、并发与人力

信息状态：动态快照｜最后核验：2026-07

价格截至 2026-07,以官方定价页为准(Anthropic、OpenAI、Google 的定价会持续调整,使用前请重新核对)。

做 AI 产品的 PM,绕不开一个问题:这个功能上线后,每个月要花多少钱?这笔账算不清楚,PRD 里的"预期效果"就是空中楼阁——功能越受欢迎,账单可能越吓人。本文教你从 token 计费的基本逻辑出发,搭一套自己能复用的估算方法。

一、token 计费怎么算

主流大模型 API 都按 token 计费,而不是按"字"或"次"计费。token 是模型处理文本的最小单位,一次调用的费用由三部分构成:

单次调用成本 = 输入 token 数 × 输入单价 + 输出 token 数 × 输出单价

几个新手常踩的坑:

  1. 输入和输出单价不同,且差距很大。几乎所有厂商的输出单价是输入单价的 5-6 倍(例如 Claude Sonnet 4.6 输入 $3/百万 token,输出 $15/百万 token)。这意味着"让模型少说话"比"少给它看材料"更能省钱。
  2. 中文和英文的 token 换算比例不同。经验估算:英文约 4 字符 = 1 token,中文约 1.5-2 个汉字 = 1 token。也就是说,同样意思的一句话,中文通常比英文消耗更多 token——这是很多国内团队实际算账时会低估成本的原因。
  3. 不同模型的分词器(tokenizer)不一样,同一段文字在不同模型上计出的 token 数可能差 20%-30%(例如 Anthropic 从 Opus 4.7 起换用新分词器,同等文本比旧模型多出约 30% 的 token)。做精确估算时,应该用对应厂商的官方工具实测,而不是套用统一比例。
  4. 系统 Prompt、历史对话、工具调用定义都算输入 token。很多团队只算"用户这句话"的 token,却漏算了系统 Prompt 和多轮历史——这往往是实际账单超出预期的头号原因。

三、完整估算案例:DAU 10 万的问答助手功能

假设你负责一款内容类 App,准备上线一个"AI 问答助手"入口,预计 DAU(日活)10 万。我们来完整算一遍月度模型成本。

第一步:列出假设

参数 假设值 依据/说明
DAU 100,000 产品现状数据
功能渗透率 30% 参考同类"入口型"AI 功能的历史渗透率,先用保守值
日活跃使用用户 30,000 DAU × 渗透率
人均日调用次数 5 次 问答类功能通常有 3-8 轮的追问
每次输入 token 600 系统 Prompt(~150)+ 检索片段/历史上下文(~300)+ 用户当轮输入(~150)
每次输出 token 250 中等长度回答
选用模型 Claude Sonnet 4.6 效果和成本的中间档,适合大多数问答场景

第二步:计算

日调用次数 = 100,000 × 30% × 5 = 150,000 次/天
月调用次数 = 150,000 × 30 天 = 4,500,000 次/月

月输入 token = 4,500,000 × 600 = 2,700,000,000(27 亿)tokens
月输出 token = 4,500,000 × 250 = 1,125,000,000(11.25 亿)tokens

月输入成本 = 2,700 × $3.00  = $8,100
月输出成本 = 1,125 × $15.00 = $16,875
月模型成本合计 ≈ $24,975

按 1 美元 ≈ 7.2 人民币折算(汇率仅作示意,请以当期汇率为准):
月成本 ≈ ¥18 万

第三步:敏感性提示

这笔账最容易失真的三个变量,上线前要单独测算区间而不是只给一个数字:

变量变化 对月成本的影响
渗透率 30% → 60%(功能爆火) 成本 ×2
人均调用 5 次 → 10 次(用户养成多轮追问习惯) 成本 ×2
换用 Opus 4.8(效果更好但更贵) 成本 ×1.67 左右
引入 RAG,输入 token 从 600 涨到 1500 成本明显上涨,输入部分 ×2.5

给管理层汇报时,建议给一个区间("¥15-30 万/月,取决于渗透率和上下文长度"),并说明触发重新评估的条件(比如渗透率超过 50% 时要复核)。关于面试中常考的"如何拆解假设""如何做敏感性分析",可参考 估算日活 100 万的 AI 对话产品每月模型调用成本。

四、别忘了:API 调用费不是全部成本

很多 PM 做 ROI 测算时只看模型 API 账单,容易大幅低估真实成本。一个 AI 功能从预研到稳定运营,完整的成本构成大致如下:

成本项 说明 量级参考(相对模型 API 成本)
模型 API 调用 上文计算的部分 基准 100%
数据标注 训练/评估数据的人工标注,尤其是效果评估集 一次性投入,视任务复杂度可达数万到数十万元
效果评估与测试 Badcase 复核、评测集维护、人工抽检 通常需要 0.5-2 名全职人力持续投入
向量数据库/检索基础设施 若功能涉及 RAG 按存储量和 QPS 计费,通常是模型成本的 5-15%
人力(算法+工程+产品) Prompt 迭代、评估体系搭建、上线运维 前期投入通常远高于 API 费用本身
GPU 资源(若自建部署) 仅在决定私有化部署时产生 需要达到一定调用规模才划算,见《模型选型决策框架》
安全与合规审查 内容安全、数据合规评估 视行业和监管要求,可能是持续性投入

一个常见的经验法则:功能上线第一年,人力和评估成本(尤其是标注与 Badcase 复核)往往和 API 调用费用同一量级,甚至更高。做预算时不要只报"模型费",要把这些一并列出,否则后续会被追加预算的问题反复问到。

五、给 PM 的估算模板

写 PRD 或做成本评审时,可以直接套用下面的模板,把假设和公式都摆在明处,方便被追问和复核:

【产品形态】:一句话描述场景(单轮问答 / 多轮对话 / Agent 多步调用 / 批量处理)

【核心参数假设】
- DAU / 目标用户规模:
- 功能渗透率:
- 人均日调用次数:
- 每次输入 token(拆分:系统 Prompt + 上下文/检索片段 + 用户输入):
- 每次输出 token:
- 拟选用模型及单价:

【计算公式】
月调用次数 = DAU × 渗透率 × 人均日调用次数 × 30
月输入成本 = 月调用次数 × 每次输入 token ÷ 1,000,000 × 输入单价
月输出成本 = 月调用次数 × 每次输出 token ÷ 1,000,000 × 输出单价
月模型成本 = 月输入成本 + 月输出成本

【非 API 成本补充】
- 标注/评估人力:
- 基础设施(向量库等):
- 是否需要预留 GPU/自建评估:

【敏感性说明】
列出 2-3 个最可能变化的参数,给出成本区间而非单一数字

这套模板配合上文的价格表,基本能覆盖大多数"某功能上线后成本多少"的评审场景。下一步该关心的是"选哪个模型才是效果、成本、延迟、合规的最优解",请看《模型选型决策框架》;如果账算出来觉得太贵,直接跳到《降本手段盘点》。算清功能账单之后,还要把同一套单位经济学接到岗责与定价评审上——见下一节。

六、隐性成本与「高薪错觉」

补充于 2026-08：选题启发自磊叔《关于 AI 产品经理的 100 个问题》Q6。正文为原创框架;不采用该文中的薪资区间、涨薪比例或「Token 占营收 X%」等未外证数字当行业标准。

看招聘价码,容易把 AI PM 想成「金饭碗」。更值得算清的是另一件事:这个岗位要为怎样的边际成本结构负责——个人包看起来高,并不等于业务的单位经济学轻松。

和传统软件差在哪

传统软件 / 经典 SaaS 大模型驱动的 AI 功能
多服务一个用户 边际成本主要是固定云资源分摊 几乎每次调用都产生 Token / 推理费用
产品「成功」意味着 规模摊薄固定成本 活跃、多轮追问、Agent 多步上升时,账单与成功绑在一起
岗责常被误读成 交付功能与增长 还要持续守住单位任务成本,并把成本底线嵌进定价

第四节列的是功能级非 API 项(标注、评估、向量库、人力、合规)。这里的「隐性」多一层含义:评审若只报模型费、不报暗成本、也不问定价能否托住,岗位溢价对应的判断责任其实没有兑现——这就是「高薪错觉」在成本语境下的所指,而不是去争论某城某档薪资该不该拿。

怎么算(框架三步,不抄百分比红线)

  1. 可见账单:用上一节模板估月度模型成本与敏感性区间。
  2. 摊到每次有效调用:把延迟损耗、人工兜底、迭代/评估摊销、基础设施、合规等写进单位成本——见《降本手段盘点》·暗成本。品类上「模型费占营收多少算健康」只能用自有财务目标校准,不要背外部分位数,见同文品类成本框架。
  3. 对照定价底线:贡献毛利能否覆盖变动推理成本与必要兜底;订阅还要看 P90 用量而不是均值——见《AI 产品定价与商业化》第五节「成本底线」。

再补一条常见误判:模型单价下降 ≠ 总成本下降。效率变好、单次变便宜后,更长上下文、更多轮、更重 Agent 形态常会把总消耗顶回去(Jevons 机制),说明见《降本手段盘点》·Jevons 悖论。

落地一句话:谈岗责或 ROI 时,把「能否独立拆清 Token + 暗成本 + 定价能否托住」当作能力锚点;具体降本组合与反模式继续读降本文,商业契约怎么选读定价文。
