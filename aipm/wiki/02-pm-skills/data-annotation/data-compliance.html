数据合规红线：用户数据能不能用来训练

本文不构成法律意见。 数据合规政策与法规更新频繁，请以厂商官方最新政策与国家最新法规原文为准；重大项目务必咨询法务或合规专业人士。文中「事实」仅复述已公开的官方法规/厂商政策要点；「建议」是产品设计与流程上的可操作动作，不等于强制法条。不确定处标「需法务 / 待核验」。

覆盖范围：本文专注训练数据侧——用户数据能否进入训练集、厂商「是否用于训练」政策、告知/同意/退出/脱敏、出境与「你自己训练」的边界。产品过审总清单（内容安全、标识、备案评估、投诉处置、中欧美对照）见 生成式 AI 合规设计清单，不在本文重复堆砌。

选题结构启发自磊叔《关于 AI 产品经理的 100 个问题》Q40（隐私进训练集何时爆）、Q88（训练红线怎么划）；正文依据下文「参考资料」中的官方原文原创撰写，不以任何第三方 PDF 条款代替法规原文。

信息核验日期：2026-08-06（以下「访问日期」同，除非另行注明）。

为什么 PM 必须懂这件事

「能不能把用户对话数据拿去训练模型」表面像法务和数据安全的题，但决策经常卡在产品设计：要不要在设置里加「数据用于改进」开关？默认开还是关？首次使用时怎么说清楚？企业客户合同里「不上训练集」怎么落到工程与日志？这些是 PM 要拍板或主导的细节——懂边界，才能在设计阶段把合规做进产品，而不是上线后被动整改。

先分清三层：谁的数据、谁在训练

把问题拆开，避免一张表答所有场景：

层级 在问什么 PM 常见误区
A. 你自己的训练 你采集的用户输入/行为/标注结果，能否用于你方预训练、微调、RLHF、评测集扩充 「用户用了产品 = 默认可训练」
B. 上游厂商训练 调用 OpenAI / Anthropic / Google 等 API 或企业版时，厂商是否会用你的客户数据训练其基础模型 「用了某家 API，等于数据进了它的公开模型」或反过来「API 不训练 = 我自己也可以随便训」
C. 消费者产品对照 厂商自己的 ChatGPT / Claude / Gemini 消费者产品，对终端用户的默认策略与开关 把消费者产品文案直接抄进 B2B 产品隐私政策

事实（厂商政策，访问 2026-08-06）：三家主流厂商对企业 / API 普遍默认不用客户业务数据训练基础模型；对消费者产品则多允许在设置可控的前提下用于改进。这只回答层级 B/C，不自动合法化层级 A。

隐私进训练集：风险通常怎么爆（对应 Q40）

风险很少是「某天法务突然发邮件说不能训」。更常见的是产品与组织层面的连锁爆点——下列是建议的风险地图，用于排期与评审，不是统计概率。

1. 模型侧「串话」与可识别信息回放

用户对话、工单、表单里常夹带手机号、地址、工号、病历片段、客户合同原文。若未做去标识化就进微调/偏好学习，模型可能在别的会话里复述或拼出可识别信息。爆点往往是用户自己发现（问产品时答出了别人的隐私），随后公关与下架压力远大于「内部合规 checklist 没勾完」。

2. 合同与渠道违约（尤其 ToB）

企业合同、采购问卷常写「客户数据不用于训练 / 不用于改进通用模型」。产品若把租户日志默认进统一训练集，或把「关闭训练」做成藏在消费者隐私页的开关却对企业账号无效，属于合同与信任双重违约——法务介入时往往已伴随客户审计。

3. 监管问询与说明义务

事实：《生成式人工智能服务管理暂行办法》第 19 条要求提供者配合监督检查，并按要求对训练数据来源、规模、类型、标注规则、算法机制机理等予以说明（全文，访问 2026-08-06）。临时拼凑「数据从哪来、有没有个保依据」会直接暴露日常缺失。

4. 开关文案与真实路径不一致

对外写「绝不用于训练」，工程上却把反馈样本、安全复核样本、匿名化后的日志持续进管线；或关闭开关后仍有安全例外却从未告知。用户与监管都对「承诺—实现」落差敏感。总清单里的「对外承诺审查」见 genai-compliance-checklist-cn.md，本文只强调：训练路径必须与隐私文案同版本号管理。

5. 「关开关」幻想：已训进模型的数据回不来

事实（厂商政策）：Anthropic 明确说明，关闭模型改进后，已开始的训练与已训练模型中的数据不会因此「撤回」；关闭只影响未来新对话进入未来训练（见其消费者条款更新 FAQ，访问 2026-08-06）。OpenAI 等亦普遍区分「停止用于未来训练」与「从已发布模型中擦除」。产品文案若暗示「一点即永久抹除训练痕迹」，属于高风险承诺，需法务审定表述。

合规红线怎么划（对应 Q88）：事实框架

各地细则不同，但面向「用户数据进训练」的产品设计，可先锚定下列可核对要求；落地适用性一律 需法务。

中国：暂行办法第 7、11 条 + 个保法

方向 事实要点（摘要） 出处（访问 2026-08-06）
训练数据处理 预训练、优化训练等须：合法来源的数据与基础模型；涉及知识产权不得侵害；涉及个人信息的，应当取得个人同意或者符合法律、行政法规规定的其他情形；提高数据质量（真实、准确、客观、多样）；并遵守网安法、数安法、个保法等 《生成式人工智能服务管理暂行办法》第 7 条，中国政府网全文 / 网信办
输入与使用记录 不得收集非必要个人信息；不得非法留存能够识别使用者身份的输入信息和使用记录；不得非法向他人提供；应及时处理查阅/复制/更正/补充/删除等请求 暂行办法第 11 条，同上
个保法叠加 目的明确与最小必要；同意须充分知情、自愿、明确；敏感个人信息等依法单独同意；处理者义务与数据主体权利 《个人信息保护法》，网信办转载

读法提醒（事实边界）：

  • 第 7 条写的是「同意或者其他法定情形」，不是「除同意外一律禁止」——是否存在其他合法处理情形、是否构成敏感个人信息、是否要单独同意，需法务按场景裁定，禁止产品自行发明「行业惯例豁免」。
  • 「提高训练数据质量」是义务方向，不是「为了效果可以先灌真实隐私再补手续」的许可。
  • 标识、备案、内容安全等过审项不在本文展开 → 合规设计清单。

欧盟 / 美国：只做对照指针

管辖 产品侧要知道的边界 出处（访问 2026-08-06）
欧盟 个人数据进训练通常落入 GDPR：合法基础、目的限制、透明与撤回、删除权等；「从已训练模型中删除」的技术与法律可行性高度场景化，禁止把「用户点删除 = 模型已遗忘」写成对外保证 GDPR EUR-Lex；AI 系统义务另见 AI Act 2024/1689 与清单文中欧对照表
美国 无与中欧同构的联邦「生成式 AI + 训练数据」统一法；常见为州隐私法（如加州 CPRA 等）+ 行业法 + 执法；具体州与行业 需法务 对照摘要见 genai-compliance-checklist-cn.md；勿背第三方读物当法条

三家大模型厂商的训练数据政策对比（访问 2026-08-06）

以下对比基于三家官方隐私政策 / 帮助中心 / 企业隐私页。消费者产品与企业/API 不能混为一谈；下表回答的是「厂商是否用你的数据训它的模型」，不是「你是否可以训自己的模型」。

厂商 消费者产品 消费者是否可控 企业 / API 默认
Anthropic（Claude） Free / Pro / Max：若开启模型改进（Improve Claude），新对话与编程会话可用于改进模型；开启时可去标识化保留至多约 5 年 可在隐私设置中开关；关闭后新对话不用于未来训练，保留回到约 30 天量级。例外：被安全系统标记复核的对话，仍可能用于安全/Usage Policy 类改进（即使关闭训练）。Incognito 对话不用于改进。关闭不回溯已训模型 Claude for Work、Enterprise、API（含 Bedrock / Vertex 等商业路径）默认不用于训练基础模型（适用其 Commercial Terms）
OpenAI（ChatGPT 等） 面向个人的 ChatGPT 等：可能用内容训练模型，除非用户退出 可在数据控制中选择「不在我的内容上训练」；退出后新对话不用于训练 ChatGPT Business / Enterprise / Edu 等及 API 平台：默认不用输入输出训练或改进模型，除非客户显式选择共享（如 Playground 反馈）
Google（Gemini Apps） Keep Activity 开启时，活动可用于提供、开发与改进服务（含训练生成式 AI 模型），并可能经人工复核 可关 Keep Activity，或用临时聊天（Temporary Chat）。官方说明：临时聊天不用于训练；Keep Activity 关闭且未提交反馈时，未来聊天不用于改进 AI 模型。关闭后账户侧保留约 72 小时（用于应答、反馈与安全保护）。已被人工复核的聊天及相关数据可保留至多约 三年，且不随你删除活动而删。设置不控制「匿名化数据用于改进服务」类处理 Workspace 企业版与 Vertex AI / API 等企业路径：默认不用于训练公开/基础模型的口径以当期企业合同与 Cloud 文档为准；管理员可进一步约束留存——选型时单独核验，待核验你方合同页

几个直接影响文案与设置项的细节：

  • 「关闭训练」≠「数据完全不被使用」。Anthropic 的安全复核例外、Google 在 Keep Activity 关闭后仍可为应答与保护（含人工复核）处理对话，都是隐私说明里最容易漏写、也最容易引发不满的点。
  • 「删除对话」≠「从已发布模型中卸载」。以 Anthropic 官方 FAQ 为例：删除对话可使其不进入未来训练；已完成的训练与已上线模型不受「关闭开关」回溯。
  • 层级 B 干净 ≠ 层级 A 干净。API 默认不训练，只说明厂商侧；你方若把对话落库再微调自有模型，仍须单独完成告知、合法依据与（如适用）出境评估。

数据出境：调用境外 API 时的训练相邻闸门

若中国用户的对话会传到境外部署的大模型 API，这通常构成向境外提供个人信息的行为，需按出境制度评估路径——与「厂商是否用于训练」是相邻但不同的问题。

事实（政策问答口径，访问 2026-08-06）：国家网信办《数据出境安全管理政策法规问答（2026年1月）》说明，关键信息基础设施运营者以外的数据处理者，自当年 1 月 1 日起累计向境外提供 10 万人以上、不满 100 万人个人信息（不含敏感个人信息）或 不满 1 万人敏感个人信息的，可通过订立标准合同或个人信息出境认证等方式；累计超过 100 万人个人信息（不含敏感）或超过 1 万人敏感个人信息的，应申报数据出境安全评估。属于《促进和规范数据跨境流动规定》第三至六条情形的，从其规定。问答原文

建议：不要假设「只是调 API、没做模型训练」就不算出境；门槛计算、是否适用例外、合同与认证材料，需法务 / 合规。过审总流程中的出境勾选项见清单文，细节闸门留在本文。

产品侧防线（建议，非法律意见）

对应「进训练集」场景，可用三层把风险压到可评审状态（建议流程，不是第 7 条原文分节）：

  1. 进管线前处理：身份与联系方式等字段去标识化 / 最小化；高敏场景（医疗、金融账户、生物识别等）默认不进通用训练集，或走单独同意与隔离语料。标注外包能否接触明文，见 标注规范怎么写。
  2. 数据集上线闸门：训练/微调数据集发布前，法务或合规审核「来源合法性、个保依据、知识产权、是否混入企业租户数据」；保留可说明材料以备暂行办法第 19 条问询。
  3. 产品授权与退出：用用户能懂的话说明是否用于训练；关键路径提供开关或同意流；写清安全复核等例外；支持查询/导出/删除请求的工单闭环（权利行使细节对齐个保法与暂行办法第 11 条）。

飞轮里「行为 → 可训练样本」的转化环节，必须挂合规责任人，参见 冷启动与数据飞轮。

PM 实操清单（仅训练数据侧）

下列勾选是建议的工作分解。内容标识、算法备案、安全评估等总清单项 → genai-compliance-checklist-cn.md。

告知与依据

  • [ ] 隐私政策/用户协议是否用白话说明：对话/行为是否用于我方模型训练或改进（层级 A）
  • [ ] 是否说明调用的第三方模型厂商默认是否训练（层级 B），以及与我方训练的区别
  • [ ] 涉及个人信息进训练时，是否已按暂行办法第 7 条准备「同意或其他法定情形」的法务结论（需法务）
  • [ ] 敏感个人信息场景是否避免「和普通条款打包勾选」（个保法；需法务确认是否适用单独同意）

退出与例外

  • [ ] 是否提供关闭「用于模型改进/训练」的路径，且足够可发现
  • [ ] 是否写明：关闭后是否仍存在安全审核、滥用检测、匿名化统计等例外
  • [ ] 是否避免承诺「删除 = 已从历史模型中彻底擦除」（与厂商及自研管线真实能力对齐）

进训练集前

  • [ ] 是否在标注/训练前做去标识化或最小化，并定义「禁止入集」字段清单
  • [ ] 多租户/企业数据是否物理或逻辑隔离，禁止误入通用训练集
  • [ ] 数据集发布是否有合规签字与来源台账（应对说明义务）

出境与供应商

  • [ ] 中国用户数据是否出境至境外部署模型；是否评估标准合同 / 认证 / 安全评估门槛
  • [ ] 供应商 DPA / 企业条款是否写明「默认不训练」、留存期限与分包商

内部流程

  • [ ] 法务/合规是否在「第一次设计数据回流」时介入，而不是上线前一周
  • [ ] 营销与销售话术中的「不训练」「不上云」是否与真实架构一致

小结

用户数据能不能用于训练，答案永远是「看层级、看法域、看合同」：消费者产品与企业/API 的厂商默认不同；你方自训与厂商代训是两件事；中国侧至少要对齐暂行办法第 7、11 条与个保法，出境另算。作为 PM，把「数据从哪来、进谁的训练集、用户是否知情、能否退出、例外是什么、已训数据怎么办」在设计阶段问清，并建立政策变更跟踪——厂商消费者条款与出境问答都在持续更新，清单需要按核验日期复核。
