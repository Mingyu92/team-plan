AI 功能上线后留存很差，你怎么分诊？

难度:⭐⭐⭐ 进阶 出现频率:中高，AI 功能运营 / 指标体系向面试常见；选题启发自磊叔《100 个问题》Q50、Q61、Q62、Q64

考察点

  • 能否把「留存差」当成结果而非病因，用路径/漏斗断点分诊，而不是一上来换模型或改 Prompt
  • 是否识破 DAU 假繁荣：新奇冲高、无效活跃、重试膨胀、入口绑架、聚合掩盖
  • 能否写清成功与回访事件（队列起点、时桶、行为队列激活假设），并对低频场景改口径

参考答案

一句话：先核对「活跃 / 成功 / 回访」定义，再沿死亡路径找最大断点，用队列（不是总 DAU）验证粘性；动作按断点选型，需要因果再开实验。

第一步：先问「差的是不是同一件事」

面试官说「留存很差」，先澄清三件事，否则后面全是空谈：

  1. 分母：有资格用户、曝光用户，还是「点过一次入口就算」？
  2. 回访事件：再次登录，还是再次完成同类任务 / 再次采纳？后者才接近 AI 功能价值。
  3. 时桶：日 / 周 / 月是否对齐产品自然周期（日活工具 vs 周报助手不同）？

只有 DAU 涨、采纳与队列留存缺失——默认未证明成功（详正课）。

第二步：排除假繁荣

误判 现象 分诊含义
新奇冲高 上线 1–2 天回访好看，随后断崖 试用热度，未必有刚需
无效活跃 打开入口、随便问一句算活跃 分母灌水，没有任务完成证据
重试膨胀 追问/重生成多，会话很「忙」 可能一次解决失败；活跃与成本双涨
入口绑架 强推送/强入口抬高 DAU 触达变了，粘性未必变
聚合掩盖 总 DAU 平稳，新队列留存掉 老用户惯性托住总数

第三步：沿死亡路径找最大断点

有资格 → 触达 → 理解边界 → 有效启动 → 任务成功 → 用户采纳 → 愿意回访 → 业务结果

哪个跳掉得最狠，就先修哪里（主指标 + 动作方向）：

断点 优先怀疑 优先动作（不是默认换模型）
触达 入口深、权限未开 分发与开通
理解 过度承诺、边界不清 预期管理、示例任务
启动 表单重、授权恐惧 降摩擦、渐进授权
成功 意图/工具/数据失败 评测集、检索、工具链
采纳 不可信、不可改、流程不许用 证据/可编辑/流程嵌入
回访 无刚需、首次翻车、竞品更省事 找激活行为；修信任与价值密度
业务 相关≠因果 预注册 OEC + 护栏做 A/B

采纳/回访断点可再套 Agentic UX 的能力 / 交互 / 信任 / 成本时延 / 组织流程归因，避免所有问题开成「再训一版」。

第四步：用队列读图，落到动作

  • 获取队列：按首次有效使用日/周看第 1 / 7 / 30 时桶；纵向比产品是否变好，横向看掉崖落在哪一段。
  • 行为队列：对比「首周做过 X」vs「没做过」的后续留存；X 应是价值行为（首次被采纳、带工具回执闭环、保存/导出），不要把「多聊几轮」当激活。
  • 低频刚需：用周/月时桶，或「下次同类任务到达时仍选 AI」的选择率，别硬用日留存向老板叙事。

场景举例（电商 AI 客服助手）

老板说「上线两周留存很差」。你先发现：DAU 靠开屏推送撑着；有效启动后任务成功率尚可，但采纳率低、转人工升；新队列第 3 天断崖。分诊结论：断点在采纳与信任（一次高后果翻车 + 不可编辑），不是模型「不够聪明」。动作：引用/证据、可撤销确认、低风险场景先建信任；推送降权后看自然队列；改动用正式 A/B 验证一次解决率与转人工护栏。

追问延伸

  • 追问 1：「DAU 很高但留存很差，算不算成功？」 → 不算证明成功。DAU 最多当流量诊断；要同时看有效启动、任务成功/采纳、队列留存、单位有效任务成本与护栏。
  • 追问 2：「你怎么定激活行为？」 → 用行为队列找与后续回访差距稳定且可解释的 X，再用实验验证因果；候选偏采纳/闭环，而非会话轮次。
  • 追问 3：「要不要对标行业 7 日留存 X%？」 → 不要当普适红线。品类、入口强度、ToB 周期差一个数量级都正常；用自家历史队列与对照组建基线，再设上线线与目标线。
