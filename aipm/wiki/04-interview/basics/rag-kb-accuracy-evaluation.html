如何评估 RAG 知识库的准确率?

难度:⭐⭐⭐ 进阶 出现频率:高,小米面经(评测专题)、科大讯飞面经均有出现

考察点

  • 能否区分检索准确率和端到端回答准确率
  • 是否理解 RAG 评测需要分环节拆解
  • 能否设计可落地的评测方案,而非只说"看效果"

参考答案

核心认知:RAG 的"准确率"不是单一指标,需要分环节评测——检索准不准、生成好不好、最终答案对不对,是三个不同问题。

分环节评测框架:

环节 评测什么 核心指标 怎么测
检索 相关知识有没有被找回来 召回率(Recall)、精确率(Precision) 标注"标准相关文档",看检索结果是否命中
重排 最相关的排前面了吗 MRR、NDCG 看正确答案在检索结果中的排名
生成 基于检索内容回答得好不好 忠实度(Faithfulness)、相关性 人工或 LLM-as-Judge 评估
端到端 最终答案对不对 回答准确率、用户满意度 构建 QA 测试集,对比标准答案

评测集构建方法: 1. 从真实用户问题中采样(覆盖高频 + 长尾) 2. 人工标注"标准答案"和"应检索到的文档片段" 3. 加入边界 case:歧义问题、多跳推理、知识库未覆盖的问题 4. 定期用新增 bad case 扩充,保持评测集与线上一致

PM 的关键动作: - 定义"什么算检索对了"(召回了就够?还是必须排第一?) - 推动建立标注流程和质量标准 - 建立迭代闭环:评测 → 发现薄弱环节 → 优化(切片/索引/Prompt) → 再评测

追问延伸

  • 追问 1:"检索召回率很高但回答还是不准,问题在哪?" → 生成环节问题:检索内容对了但模型没用好,或 Prompt 引导不当;也可能是切片粒度问题(信息被截断)。
  • 追问 2:"知识库更新了怎么保证评测集不过时?" → 定期同步更新评测集;用线上新问题和用户反馈持续补充;设置"知识库覆盖率"指标监控盲区。
  • 追问 3:"RAG 准确率和传统搜索准确率能直接对比吗?" → 不能直接比:RAG 是"检索 + 生成"的端到端效果,传统搜索只看文档排序;但检索环节的指标可以横向参考。
