Prompt、RAG、SFT 分别是什么?有什么区别?

难度:⭐⭐ 入门必备 出现频率:极高,抖音校招、大厂常见题均有出现

考察点

  • 能否区分三种手段的作用层级(指令层 / 知识层 / 能力层)
  • 是否理解成本、迭代速度和适用场景的差异
  • 能否给出"从轻到重"的技术选型思路

参考答案

一句话对比:Prompt 是"怎么问",RAG 是"查什么资料再答",SFT 是"把行为模式写进模型"。

维度 Prompt RAG SFT(监督微调)
本质 推理时给模型的指令和上下文 检索外部知识拼进 Prompt 用标注数据继续训练模型权重
改变什么 不改变模型,只改变输入 不改变模型,改变输入中的知识 改变模型本身的行为模式
成本 最低,改文字即可 中等,需建知识库 + 检索链路 较高,需标注数据 + 训练资源
迭代速度 分钟级 小时到天(改库即可) 周级(需重新训练)
擅长解决 输出格式、角色设定、简单约束 私有知识问答、需溯源的场景 领域话术、固定格式、行为习惯

选型口诀:先用 Prompt 试效果 → 知识不够加 RAG → 风格/行为改不了再考虑 SFT。三者可组合,很多产品是"Prompt 工程 + RAG + 微调模型"的叠加方案。

产品视角:面试时重点不是背定义,而是能举例——"客服机器人要回答公司最新政策"用 RAG;"要让模型按固定 JSON 格式输出"先用 Prompt,不行再 SFT。

追问延伸

  • 追问 1:"Prompt 优化到极致了还是不行,你怎么判断该上 RAG 还是 SFT?" → 知识类问题(模型不知道)走 RAG;行为类问题(模型知道但做不好)走 SFT。
  • 追问 2:"SFT 需要多少数据?" → 没有标准答案,重点是"取决于任务复杂度,几百到几万条不等;数据质量远比数量重要"。
  • 追问 3:"三种手段的成本结构分别是什么?" → Prompt 是每次请求的 token 开销;RAG 多了建库和检索成本;SFT 是一次性训练成本 + 后续推理成本。
