找工作 · 答题方法

面试题怎么拆

不会答，多半不是不会知识，是不知道这题在问什么。这里只有两样东西：一套拆题动作，和六类题的骨架。

不知道答案的时候，先说这三句

这不是糊弄。面试官要的是「这个人遇到没做过的事会怎么动」，不是标准答案。

  1. 「我会先看三件事：……」——把判断标准说出来，哪怕结论还没想好。
    例：这个功能值不值得做，我会看用户是不是真的重复遇到这个麻烦、技术上能不能稳定做到、成本能不能回来。
  2. 「具体怎么定，我会先做个小验证：……」——说出你下一步会做什么。
    例：先拿 50 条真实数据跑一遍，看准确率够不够，再决定要不要投人力。
  3. 「所以我现在的判断是 A，但如果 X 成立，我会改成 B。」——给结论，同时留出条件。
    这样即使结论错了，面试官看到的是「会做决策」，不是「背了答案」。

第一步：先判断这题在问什么

题目长相它在考答题骨架
「该不该用 AI」「自研还是接第三方」判断与取舍目标 → 约束 → 三条判断线 → 结论
「设计一个……」「你会怎么规划」方案能力用户 → 目标 → 方案分层 → 兜底 → 验证
「怎么衡量」「PMF 怎么判断」「怎么归因」指标与实验定义成功 → 指标分层 → 实验 → 归因
「RAG / 微调 / Agent / MCP 怎么回事」技术理解是什么 → 解决什么 → 何时不用 → 怎么衡量
「讲讲你这个项目」项目深挖背景 → 我的动作 → 关键取舍 → 结果 → 反思
「为什么做 PM」「你最大的缺点」动机与性格情境 → 选择 → 结果 → 认知

六类题的骨架 每类一个公式 + 一个示范

① 判断与取舍题

该不该用 AI / 自研还是买
目标 → 约束 → 三条判断线 → 结论 + 怎么验证

三条判断线（背下来，几乎所有取舍题都能套）：

① 价值：用户是不是真的重复遇到这个问题，不用 AI 有没有更便宜的办法。
② 边界：现在的模型能不能稳定做到，做不到的那部分谁来兜。
③ 成本：token、延迟、数据标注，算下来比人工便宜还是更贵。

示范：「客服工单分类该不该上大模型？我的判断是先用规则 + 小模型，把大模型放在最难的那 20%。
价值上，工单量大、分类标准比较统一，值得自动化；
边界上，标准类目规则能覆盖 80%，剩下的长尾描述才需要语义理解；
成本上，全量走大模型每次调用都花钱，长尾才调用能省一半。
所以先按 80/20 切，跑两周看规则覆盖率，再决定要不要扩大模型比例。」

别一上来就答「用 RAG」。先回答值不值得做，再回答怎么做。

② 方案设计题

设计一个 AI 功能 / Agent
用户与场景 → 成功长什么样 → 方案分层 → 失败怎么办 → 怎么验证

开口前先反问三句（面试官喜欢这个动作）：用户是谁、成功怎么算、有什么硬约束（预算、合规、上线时间）。

方案分四层讲：数据从哪来 → 模型怎么选（现成 API / 微调 / 规则） → 交互怎么设计（用户怎么知道它在干什么、错了怎么改） → 兜底（模型答不出转人工、给不出来就说给不出来）。

示范：「给新商家做带货短视频生成。
用户是不会拍视频的小商家，成功标准是『生成后能直接投，不用再改』。
数据用商家的商品图 + 卖点文案；模型先用现成的视频生成 API，不自己训；
交互上给三个模板而不是空白输入框，因为小商家不会写 prompt；
兜底是生成失败或审核不过时，退回图文模板。
先放 50 个商家灰度，看首次可用率和二次修改率。」

不要只讲功能列表。要讲「哪一层用什么技术、为什么不用另一条路」。

③ 指标与实验题

PMF / 北极星 / 归因 / A/B
定义成功 → 指标分三层 → 实验怎么设 → 结果怎么归因

指标三层：北极星（一个数）→ 过程指标（哪一步掉）→ 护栏指标（不能被牺牲的，比如投诉率、成本）。

AI 产品的特殊性：输出有随机性，样本量要更大；「用户点了赞」不等于「真的有用」，要看有没有回流使用。

示范：「AI 搜索助手的北极星我会用『一周内重复使用的人数』，不用点击率——点击只能说明好奇。
过程指标看：提问后有没有追问、有没有点开引用来源、有没有转人工；
护栏看：单次成本、平均响应时长、错误回答的投诉率。
A/B 的话，按用户分流，实验组用新检索策略，至少跑两周覆盖一个完整使用周期，因为新功能第一周的新鲜感会骗人。」

被问「短期好长期差」时，答案是「新鲜感衰减」+「没进入工作流」，然后给验证办法。

④ 技术理解题

RAG / 微调 / Agent / MCP / 上下文
是什么 → 解决什么问题 → 什么时候不该用 → 怎么判断它好不好

不要背流程，背流程一听就是背的。改成讲取舍：

· RAG 解决「知识会过期、私有数据进不去」；代价是检索不准就答不准。
· 微调解决「风格和格式要稳定」；代价是数据贵、改一次要重训。
· Agent 解决「要多步、要调工具」；代价是不可控、贵、慢。
· 上下文管理解决「聊久了记不住」；代价是压缩会丢信息。

示范：「RAG 和微调不是二选一。我的判断是：事实类的知识放 RAG，因为要能更新、要能指出来源；表达类的要求（比如必须按固定格式输出、语气统一）才考虑微调。
如果两个都要，就先 RAG 上线，把 badcase 攒起来，看是不是格式问题再决定要不要微调。」

如果被追问原理讲不出来，就退到「我知道它解决什么、什么时候会失效」，别硬编。

⑤ 项目深挖题

讲讲你的项目 / 最大的难点
背景一句话 → 我的动作 → 一个关键取舍 → 结果数字 → 如果重来

面试官只听三件事：这事是不是你做的、你做了什么判断、结果怎么证明。

准备时把每个项目压成 5 行，每行一句话。数字必须能回查——被追问「这个数怎么来的」答不上来，比没有数字更糟。

示范结构：「这个项目要解决的是 X（背景）。
我负责的是 Y（边界要清楚，别把团队成果说成自己的）。
中间最难的判断是 Z，我当时选了 A 没选 B，因为……（这是面试官最想听的）。
最后结果是 N（数字 + 口径）。
如果重来，我会更早做 M。」

「我们团队」讲太多会被认为没干活；「我」讲太多要能接住追问。

⑥ 动机与性格题

为什么做 PM / 优缺点 / 压力
情境 → 选择 → 结果 → 认知

不要讲形容词（「我很有责任心」），讲一件小事。小事比大词可信。

示范：「为什么做产品——我做过一段时间研究，最享受的不是把指标刷上去，是把一个别人说不清的问题拆成能做的事。
有一次……（一件具体的小事）。
所以我想做离用户近一点、能拍板的工作。」

别说「我沟通能力强」。给一个你协调过谁、怎么协调的。

练的时候只做一件事

每题先说骨架，再补内容

拿真题页随便挑一道，先不答内容，只说出：「这题属于哪一类，我用哪个骨架」。这一步 10 秒。

骨架对了，内容哪怕朴素也是及格；骨架错了，内容再熟也像背书。

一天 3 道，一道 3 分钟口述，录音回放。说不到 1 分钟的，就是没想清楚，回去补那一块。

骨架是通用的，示范里的数字和场景是举例，不要当成你的经历去讲。
